## 2024-07-08 - Prevent per-second statistics recalculation
**Learning:** SwiftUI anti-pattern found: doing O(N log N) array filtering and sorting inside computed properties of a view (`StatisticsView.swift`) that observes an `AppModel` triggering updates every second (on timer tick). Swift `Array` equality checking is `O(1)` when unmodified due to buffer identity, making it extremely efficient to use as a dependency in `.onChange`.
**Action:** Cache expensive derived data calculations using `@State` variables and `.onChange(of: filterParams)` rather than computing them directly inside properties that will be evaluated on every single View render.
## 2024-07-09 - Avoid Calendar components inside tight loops
**Learning:** Calling `Calendar` methods (like `.component(_:from:)`) or date math inside tight loops is a severe performance bottleneck due to ICU overhead. In our `StatisticsView.swift` which re-evaluates frequently, recalculating statistics using these methods caused extreme CPU thrashing.
**Action:** Pre-calculate the bounding `DateInterval` for the period using `Calendar.dateInterval(of:for:)` *before* the loop, and use `DateInterval.contains(_:)` inside the loop for O(1) checking.
