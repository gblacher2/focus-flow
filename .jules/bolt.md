## 2024-07-08 - Prevent per-second statistics recalculation
**Learning:** SwiftUI anti-pattern found: doing O(N log N) array filtering and sorting inside computed properties of a view (`StatisticsView.swift`) that observes an `AppModel` triggering updates every second (on timer tick). Swift `Array` equality checking is `O(1)` when unmodified due to buffer identity, making it extremely efficient to use as a dependency in `.onChange`.
**Action:** Cache expensive derived data calculations using `@State` variables and `.onChange(of: filterParams)` rather than computing them directly inside properties that will be evaluated on every single View render.
## 2024-09-26 - Pre-compute DateIntervals to avoid Swift Calendar overhead in loops
**Learning:** Using Swift `Calendar` methods like `calendar.component(_:from:)` or `calendar.isDate(_:inSameDayAs:)` inside tight loops (such as filtering an array of session records) creates severe performance bottlenecks due to the heavy ICU date math overhead on every iteration.
**Action:** Always pre-calculate the boundaries using `calendar.dateInterval(of:for:)` outside of loops, and then use the `DateInterval.contains(_:)` method inside the loop. This changes the complexity of the check from an expensive O(N) ICU operation to a simple O(1) mathematical bounds check.
