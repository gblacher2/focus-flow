## 2024-07-08 - Prevent per-second statistics recalculation
**Learning:** SwiftUI anti-pattern found: doing O(N log N) array filtering and sorting inside computed properties of a view (`StatisticsView.swift`) that observes an `AppModel` triggering updates every second (on timer tick). Swift `Array` equality checking is `O(1)` when unmodified due to buffer identity, making it extremely efficient to use as a dependency in `.onChange`.
**Action:** Cache expensive derived data calculations using `@State` variables and `.onChange(of: filterParams)` rather than computing them directly inside properties that will be evaluated on every single View render.
## 2024-07-08 - O(N) Calendar Lookups During Array Filtering
**Learning:** Avoid using `Calendar` methods (like `.component(_:from:)`) inside tight loops, such as `.filter` or `.reduce`, as they cause severe performance bottlenecks due to ICU date math overhead. Swift's `Calendar` functions are notoriously slow when called repeatedly.
**Action:** When filtering collections of dates, pre-calculate `DateInterval`s (e.g., using `calendar.dateInterval(of: .day, for: date)`) before the loop. This turns O(N) Calendar component lookups into O(1) comparison checks (`interval.contains(date)`). Never hardcode durations (like 86400 seconds) due to Daylight Saving Time edge cases.
